Methodology

How whiff skill is measured, how the model is built, and what the numbers mean.

What Is Whiff Skill?

Not all pitchers face the same quality of hitters, and not all pitches are equally hittable. A fastball at the knees is harder to put the bat on than a hanging breaking ball at the belt. If we simply count whiffs, we're conflating pitcher ability with the quality of pitches thrown.

Whiff Skill = Actual Whiff Rate − Expected Whiff Rate

The model estimates an expected whiff rate for each pitch — the rate an average MLB batter would be expected to miss given that exact pitch physics and game situation. The pitcher's skill is how far their actual results deviate from those expectations.

  • Positive skill means the pitcher generates more whiffs than their pitch quality predicts — they have genuine swing-and-miss ability.
  • Negative skill means batters are making more contact than the pitch physics would suggest.
  • Zero skill means the pitcher is performing exactly as their pitches predict.
The model sees only pitch physics and game state — not the pitcher's name, team, or history. This ensures that skill reflects what the pitcher does above and beyond their stuff, rather than just having good stuff.

Model Architecture

Predicting whiffs requires answering two questions: did the batter swing? And if so, did they miss? These are different prediction problems, so we use a two-stage cascade.

Model 1 — Swing vs. Take

XGBoost binary classifier on all pitches. Balanced classes (~52% takes, ~48% swings). 500 rounds with early stopping.

Model 2 — Whiff vs. Contact

XGBoost binary classifier on swings only. Class imbalance handled with scale_pos_weight=3.26 (whiffs are ~23.5% of swings). Regularized with max_depth=4, min_child_weight=5.

Probability outputs go through isotonic calibration — a non-parametric post-processing step that maps raw XGBoost scores to well-calibrated probabilities. This reduces the Brier score by ~25% on the test set.

Pitch Clustering

Before training, each pitcher's pitches are clustered by physical characteristics (velocity, spin rate, movement, release point) using Gaussian Mixture Models with BIC-selected k=2–6 clusters. The most common pitch type in each cluster becomes its label (pitch_type_mode). This is a cleaner signal than raw Statcast pitch type classifications, which can be inconsistent for similar pitches.

All splits are strictly temporal — no data from future seasons appears in earlier training sets. This prevents any form of lookahead bias.

Feature Design

What's Included

  • Pitch physics: velocity, spin rate, horizontal and vertical movement (pfx_x, pfx_z), acceleration components (ax, ay, az)
  • Trajectory / deception: time_to_plate, late_break_z/late_break_x (movement per second), approach_angle_z/approach_angle_x
  • Batter-relative coordinates: plate_x_batter flips the horizontal axis for left-handed batters so "inside" always means the same thing regardless of handedness
  • Zone analysis: in_zone, distance outside zone (x_out_mag, z_out_signed), batter's personal zone height (plate_z_rel)
  • Game state: count (balls-strikes), two-strike flag, runners on base, score differential bucket
  • Pitch type: one-hot encoded cluster label (FF, SL, CH, CU, etc.)
  • Handedness matchup: same_side flag (pitcher/batter same hand)

What's Deliberately Excluded

Cluster-derived physical statistics — mean velocity, mean spin, mean movement per pitcher-cluster — are computed but excluded from training. These features encode pitcher identity; including them would mean "expected" is partially determined by who threw the pitch, defeating the purpose of skill isolation.

The goal is for expected to represent what an average batter does against this exact pitch, not against this pitcher's typical pitch. Nine cluster-derived features are excluded for this reason.

Calibration

A well-calibrated model means: when it predicts 80% probability, the actual rate is close to 80%. Calibration is critical for the skill metric — if probabilities are biased, the "expected" values are wrong and skill scores become noise.

Isotonic calibration reduces the Brier score from 0.1899 to 0.1420 on the test set — a 25% improvement. The model's out-of-zone breaking ball probabilities illustrate how good the calibration is:

When the model predicts ~90% whiff probability, the actual rate is 91.8%. The errors are under 1.5 percentage points across the full range.

The Two-Problem Discovery

Deep analysis revealed that whiff prediction is actually two different problems requiring different thinking:

In-Zone Pitches (65% of swings) — Rare Event Detection

Whiff rate is 14.4% — a rare event. The model achieves only PR-AUC 0.27 here. This is the hardest part of the prediction task: most in-zone swings result in contact, so predicting which ones don't requires very fine signal.

Out-of-Zone Breaking Balls (12% of swings) — Balanced but Chaotic

With a 52.6% whiff rate, this is essentially a coin flip on average. But the model is not just predicting 50% — it achieves PR-AUC 0.81 here. The key insight is that the model finds real signal: when it predicts >80% probability, the actual whiff rate is 91.8%. When it predicts <30%, the actual rate is 22.7%.

The high PR-AUC ceiling of OOZ breaking ball predictions doesn't mean the model is better at predicting them — it means there's more separable signal in the data. The in-zone rare event problem is where the biggest opportunity for improvement lies.

Both problem types are kept in the model rather than filtering. Removing OOZ breaking balls would bias skill metrics toward easier-to-predict pitches, and those are often exactly where skill differences emerge most clearly.
